# bun-password-and-load-bugs

Objective: replace the `argon2` package with `Bun.password` without breaking stored hashes, and resolve `bugs/load.bug.md` with RED->GREEN probes.
Branch: `feat/users` (earlier work is still uncommitted, so there are no work-unit commits). Test runner: `bun test`; load probes run k6 against sabotaged servers.

## Specs

- S1. "Migra argon2 hacia la integracion de bun": `Argon2PasswordHasher` uses `Bun.password` (argon2id); the `argon2` dependency is removed.
- S2 (assumption, required by S1). Hashes already stored by the `argon2` package (`$argon2id$v=19$m=65536,t=3,p=4$...`) still verify, so existing users can sign in.
- S3. "también revisa como lo hemos hecho anteriormente en @bugs/load.bug.md": one RED->GREEN probe per load bug.
  - L-01 "Expected statuses should be scoped strictly to individual requests or scenarios ... never applied as a blanket rule to the entire engine."
  - L-02 "`setup()` must either clean up matching pool users beforehand or handle 409 by treating existing pool users as already provisioned."
  - L-03 "`isAuthResponse`: Assert `typeof body.user.id === 'number'` and `body.token.split('.').length === 3`." (+ the `Content-Type: application/json` header)
  - L-04 "`hasErrorShape`: Assert `error`, `message`, `path`, and ISO `timestamp`."
  - L-05 "Add sign-in attempts for non-existent names to stress test the Argon2 dummy hash under concurrency."
  - L-06 "Use an explicit delimiter (e.g. `load_${runId}_%`) and validate that `runId` is non-empty before executing deletion." (names must be alphanumeric, so the delete matches an exact anchored pattern instead of using `_`)
  - L-07 "Add a spike stage (e.g. 30 VUs burst) to measure server behavior and fail-safes when saturated."
