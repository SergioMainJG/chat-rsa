# load-messages-bugs

Objective: one strict test file per bug in `bugs/load.bug.md` (Run 2, `messages` integration); RED before any source fix, GREEN after.
Branch: `feat/messages` (no git usage: the user owns git, so no work-unit commits). Test runners: `bun test` (unit/integration against the `chat-rsa` pod) and `bun run test:load:probes` (k6 `grafana/k6:2.4.0` via Podman).

## Specs

- S1 (BUG-CRITICAL-01). "Parameterize the k6 script in `runK6` and add a dedicated `messages.load.ts` + `messages.load.sabotage.test.ts` (and `fake-messages-server.ts`) exercising REST room/key/history endpoints, `429` rate-limit boundaries, and concurrent `/ws` `k6/ws` sessions (message fan-out, idempotency retries, epoch rotation, and receipts)."
- S2 (BUG-CRITICAL-02). "In `scripts/load.ts`, delete rooms involving matching load-test users first (...), then `DELETE FROM users WHERE name ~ ${ownUsers}`, and wrap `await sql.close()` in an inner `try/finally`."
- S3 (BUG-CRITICAL-03). "1. `scripts/load.ts` should clear or namespace rate-limit keys in Valkey between load test runs. 2. `fake-auth-server.ts` (and a new `messages` load suite) should model the token-bucket rate limiter (`429` with `Retry-After`), and `test/load/` should explicitly verify that bursts exceeding the IP/user bucket receive `429` with a valid integer `Retry-After` header and `hasErrorShape(r, 429, path)`."
- S4 (BUG-CRITICAL-04). "`isAuthResponse` in `auth.load.ts` must base64url-decode the JWT header and payload segments and assert `header.alg === 'HS256'`, `payload.sub === String(body.user.id)`, `payload.name === name`, and `typeof payload.exp === 'number'`. Add a sabotage mode (`broken-jwt-claims`) in `fake-auth-server.ts` and `auth.load.sabotage.test.ts` to prove `isAuthResponse` rejects tokens missing `sub` or `exp`."
- S5 (BUG-HIGH-05). "1. In `fake-auth-server.ts`, track `poolReuses` (how many `409` -> `/api/auth/sign-in` reuse verifications occurred) and assert `expect(outcome.poolReuses).toBe(20)` in `L-02`, plus add a `pool-wrong-password` sabotage asserting `expect(outcome.exitCode).toBe(SCRIPT_EXCEPTION)`. 2. Include a unique per-attempt suffix or clean up `u<n>` users in `setup()` so `signUp()` does not collide on retry."
- S6 (BUG-HIGH-06). "Add prefix-invalid test cases (e.g. `'%mwdo1ixq'`, `'.*|mwdo1ixq'`, `' mwdo1ixq'`) to `k6-runner.test.ts`, and append cryptographic randomness to `newRunId()` (e.g. `${Date.now().toString(36)}${crypto.randomUUID().slice(0, 8)}`)."
- S7 (BUG-HIGH-07). "In `hasErrorShape`, verify exact `STATUS_TEXT[statusCode]` and non-empty `errors` array on `400` validation responses; split `stripped-errors` in `auth.load.sabotage.test.ts` (or unit-test the validator predicates) so each required error property is verified independently."
- S8 (BUG-MEDIUM-08). "Extract and test the runner orchestration logic of `scripts/load.ts`, add an `AbortSignal.timeout(5_000)` to the pre-flight check, name the Podman container (`--name k6-${runId}`) so `SIGINT`/`SIGTERM` stops it deterministically, and ensure `finally` cleanup always executes."

Assumptions:

- S1: `bun run test:load [smoke|load|stress] [auth|messages|all]`, default `all` (both suites, one after the other, bucket reset in between); messages load users are `load<runId>m<n>`, so `runUserPattern` becomes `^load<runId>[pum][0-9]+$`.
- S2: deletes rooms whose members are all users of this run (and rooms they created); a mixed room with a foreign member makes the cleanup fail loudly instead of deleting someone else's room. Messages a run user sent elsewhere are deleted before the user.
- S3: the fake's honest mode models the server's default IP bucket (capacity 120, refill 20/s). `stress` gets a `rate_limit` burst scenario whose 429s must carry an integer `Retry-After` and the error shape; `spike` keeps its expected statuses, so a rate-limited server still fails `stress` on purpose (as CLAUDE.md documents). Bucket reset deletes only `rl:ip:` for loopback addresses and `rl:user:<id>` for this run's users.
- S8: the pre-flight also pings PostgreSQL and Valkey, since `GET /` never touches them.
