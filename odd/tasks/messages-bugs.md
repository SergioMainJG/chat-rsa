## Specs

- S1 (BUG-CRITICAL-01). "`SendMessageUseCase.execute` (or `PostgresMessageRepository.append`) must verify `message.roomId === room.value.id` when `duplicate === true` and return `err(new ConflictError('idempotencyKey was already used for another message'))`. Additionally, the database trigger `messages_assert_sender_is_member` should enforce `NEW.key_epoch = rooms.key_epoch`."
- S2 (BUG-CRITICAL-02). "Wrap `senderKeys.store` in a transaction or database guard that verifies `rooms.key_epoch` and maps `SQLSTATE 23503` on `sender_key_envelopes_room_id_sender_id_fkey` (`ForbiddenError`) and `sender_key_envelopes_room_id_recipient_id_fkey` (`ConflictError` / `ValidationError`), returning `Result.err(...)` instead of throwing an unhandled 500 error."
- S3 (BUG-CRITICAL-03). "`PostgresReceiptRepository.advance` (and `InMemoryReceiptRepository.advance`) should throw `ForbiddenError('You are not a member of this room')` when no `room_members` row matches, and `ReceiptUseCase.execute` should catch `ForbiddenError` and return `err(error)`."
- S4 (BUG-CRITICAL-04). "Either require all room members to have published identity keys before `ensureEpoch` marks the epoch prepared for all members, or retain wrap capability / rotate the sender's chain key when a member without an envelope publishes their identity key."
- S5 (BUG-HIGH-05). "`ChatController.#onReady` must always reload rooms (`await this.#reloadRooms()`) so `keyEpoch` and `memberIds` are fresh after a reconnect; on a `conflict` stop (or before a `conflict` retry), `ChatController` must reload the room's current `keyEpoch` from `GET /api/rooms`, and if `idempotencyKey was already used for another message` occurs, treat it as a permanent rejection instead of livelocking the outbox."
- S6 (BUG-HIGH-06). "Reject timestamps `< 0` and `since >= until` in `historyQueryOf`; add unit tests for `limit = \"1\"`, `limit = \"100\"`, `rows.length === limit`, and `limit >= 3` (where `page.at(-1) !== page.at(+1)`)." Plus: "handle `since === 0` without excluding millisecond `0`."
- S7 (BUG-HIGH-07). "Track whether presence was actually announced per user (or announce from the first socket that completes `welcome`), send `presence.snapshot` / `presence` on `events.membersChanged`, and test `presence.snapshot` with offline members."
- S8 (BUG-HIGH-08). "Add unit tests covering UUID prefix/suffix rejections, non-canonical base64 chunks, `MemberId.create(2_147_483_647)` (accepted) vs `MemberId.create(2_147_483_648)` (rejected), and exact error objects for `KeyEpoch` and `ChainIndex`."
- S9 (BUG-HIGH-09). "Test single-field validation failures independently in every use case, test `AddMemberUseCase` with invalid `userId`, test `FetchSenderKeysUseCase` with explicit valid and invalid `keyEpoch` query values, and assert `400 ValidationError` for malformed `roomId`."
- S10 (BUG-MEDIUM-10). "Add fault-injection integration tests (similar to `user.datasource.fault-injection.integration.test.ts`) verifying that non-mapped `SQL.PostgresError` codes and generic errors rethrow as 500 errors."
- S11 (BUG-MEDIUM-11). "Assert in unit tests that `inFlight` and heartbeat timers are cleaned up when frames settle and sockets close; in `ChatController.leaveRoom`, purge queued outbox entries, `#localTexts`, `#online`, and `#undecrypted` for the departed room."
- S12 (BUG-MEDIUM-12). "Add negative unit tests for each type guard in `chat.api.guards.ts` (including arrays with one valid and one invalid item), unit-test `systemScheduler` timer clamping/cancellation, and test IndexedDB/DOM adapters with a lightweight fake or headless harness."

Assumptions: S2 maps both foreign keys and a stale epoch inside one transaction that locks the room row (`SELECT ... FOR SHARE` on `rooms`), so a concurrent join cannot slip a stale epoch in. S6 rejects only `since > until`: the bug is the inverted window, and `since == until` is a valid empty half-open window already pinned by an existing test. S12's IndexedDB/DOM adapters (`chat.page.ts`, `messaging.outbox.indexed-db.ts`, `messaging.browser.ts`) need a browser or a fake IndexedDB that the stack constraints forbid adding as a dependency; they are covered only where a hand-written fake suffices.
